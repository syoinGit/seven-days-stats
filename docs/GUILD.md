# 無人の冒険者ギルド（軽量初期版）

## 実装範囲

- 公開の `/guild`：酒場（ドットの部屋）が唯一の画面。日付固定の最大10人の来店（V59で席を10に）。酒場はカウンター・テーブル席・依頼掲示板・暖炉・円卓の5か所に分かれ、一度に1か所を中から見た絵で表示する（主観視点）。部屋の上のバー（国の酒場への切り替え・ビールを出す・ダンジョンと同じ1本の欄）の「店内」で場所を選ぶ（JSなしでも動く。場所ごとに人数分の点と、会話中の場所に灯りの印。ラジオはバーと部屋より前に置き、`:checked ~` が両方に届く）。誰がどこにいるかは `GuildTavern` が保存せずに決める：今日の会話の組を新しい順に、テーブル席の2卓（各3席）へ同じ卓に座らせ、残りの人は日付と時間帯から決まる順でカウンター（3）・テーブル席・掲示板（3）・暖炉（3）に散らばる（朝・昼・夜で入れ替わる。定員の合計15で最大10人は必ず収まる）。その夜のダンジョンから戻った仲間（最大4人）は円卓にまとまって座り、壁には探索の地図と盾、踏破か一部達成なら卓の上に戦利品が光る。最初に映すのは会話中の人がいる場所、次に仲間が戻った円卓、いなければカウンター。会話していない人の吹き出しは、その人の話し方といる場所に合ったひとりごと（`guild/voices.yml`。日付と時間帯で変わる）。JSが動く画面では、今の会話のせりふを一人ずつ順番に吹き出しで流し（4.5秒ごと、最後のあと少し間をおいて繰り返す）、ほかの人も時々ひとりごとをつぶやく。絵はCSSで描き、眺めていられるよう少しずつ動く：住人はその場で左右に少し歩き、ジョッキから湯気、ランプのまたたき、窓の光の中の埃、暖炉の炎と火の粉、カウンターの猫のまばたきとしっぽ、テーブル席の床を時々横切る猫、暖炉前で眠る猫と「z」、掲示板の貼り紙が1枚すきま風で揺れる。窓の空は朝・昼・夜で変わる。掲示板の絵は飾り（依頼掲示板の窓は廃止）。動きを減らす設定（prefers-reduced-motion）では止まる。スマホ幅では会話の吹き出しを常時は出さず、名札の「…」で会話中を示す（押すと吹き出し）。入口はどのサイトでもヘッダー右のジョッキと剣のアイコン。
- 看板娘「ミレ」との会話（1日1回）：**いまは停止中**（ボタンとダイアログをページに出していない。`/guild/signboard` とスクリプトは残してある）。以前は酒場の上の「看板娘と話す」から、看板に描かれた娘ミレと話す。ドットの立ち絵（`static/img/guild-signboard.svg`。64×76の陰影つきドット絵、表情7種とまばたき。どれも同じ大きさの重ね絵で、記号名は変えていない）とカウンターの絵、名札つきの文字送り（押すと全文→次へ）、用意された選択肢だけで進む（自由入力やAIは使わない）。台本は `guild/signboard.yml`（`GuildSignboard`）：日付で決まる挨拶ひとつと、8つの話題（ギルド、三つの村、信仰、派閥、ダンジョン、酒場の過ごし方）から日付で選ぶ3つ、最後に別れの挨拶。せりふには今日の公開情報だけを差し込む（酒場にいる人数、存命の住人数、いちばん新しい住人の名前、今夜の探索の状況と仲間、村・派閥・信仰ごとの存命の人数）。その情報がないせりふは推測で埋めずに省く。台本は起動時に検証する（表情・条件・差し込み名、選択肢の行き先、どの話題からも届かない場面がないこと）。台本は `GET /guild/signboard`（公開・JSON）で、ボタンを押したときに取りに行く。「今日話したか」は東京の日付でブラウザの localStorage にだけ残し、サーバーには何も保存しない（別のブラウザや削除後はまた話せる。厳密な1日1回ではない）。今日すでに話していれば短い「また明日」だけを返す。JSが動かない画面ではボタンを出さない。動きを減らす設定では文字送りと立ち絵の動きを止める。
- **3つの国と無人のギルド（V66）**：世界は3つの国（今の3村：グランフォード・エルムウッド・月影郷）と、その真ん中にある無人の冒険者ギルド（ここまでの酒場）でできている。住人が暮らすのは国だけ（`current_village`。新しい住人は誕生時に決まる村に住む）で、毎日、無人のギルドに全住人から10人（来店者がときどき親しい人を連れてくる。下の「交流」）、各国の酒場（グランフォード「樫の盾亭」・エルムウッド「苔灯りの宿」・月影郷「月見茶屋 朧」）にはギルドに来なかったその国の住人から5人ずつが集まる（`GuildPlaces`。選ぶ順は従来どおり、生まれたばかりの人→最後の来店から長い人→ランダム）。席番号は日ごとに全体で一意（ギルド0〜9、グランフォード10〜14、エルムウッド15〜19、月影郷20〜24）。酒場の上の4つのリンクで場所を切り替える。国の酒場は `/guild/towns/{grantford|elmwood|tsukikage}`（公開）で、1部屋に5席の長卓、国ごとの絵（グランフォードは石造りの広間に旗・古い盾・燭台の輪・樫の卓、エルムウッドは大樹の中の宿に光る苔のランプ・蔦・丸窓・根の卓、月影郷は障子・提灯・暖簾・掛け軸・畳と低い卓、夜は丸窓に月）をCSSで描く。会話中の二人は真ん中の2席に座る。店内の場所・看板娘・ダンジョンはギルドだけ。人物の窓には「今日いる場所」を出す。
- **住人との会話（V67）**：毎日22:30 **Asia/Tokyo**（書けなかったときは22:40・22:50に再試行。失敗の回数はメモリにだけ数える）に、今日どこかの酒場（ギルドか3国の酒場）にいる存命の住人から1人をランダムに選び、AIがその人に合った会話を1つ作る（`GuildTalks`・`GuildTalkWriter`、`T_GUILD_TALK`・`T_GUILD_TALK_CHOICE`）。会話は住人の最初のひとこと（40〜120字）と、旅の人の返事3つ（共感・質問・冗談のように向きを変える）、それぞれへの住人の返し（40〜140字）。AIへの入力は名前・年齢・性別・職業・人となり・紹介・話し方・暮らす国・派閥・信仰・今いる店だけで、プレイヤーの情報や生まれた記憶は渡さない。応答は、ほかの住人の名前、死亡・結婚・交際・派閥や信仰の変化・移住、ゲームやプレイヤーやAIの話、記号やURLを含むと捨てる（定型文の代わりはない）。メンテ画面の「会話を1つ作る」でも1日1回まで作れる（定時の分とは別。`UNIQUE (talk_date, origin)`）。同じ日に同じ住人は選ばれない。Bedrockは1回最大1000出力トークン・45秒。
  - **ビールを出す**：ギルドの酒場の上の「ビールを出す」を押すと、会話を持っている存命の住人からランダムに1人がやってきて、すぐにその人との会話が始まる（`GET /guild/beer`、公開。人物の窓と同じ会話の部品を返す）。その日にもう話した住人（ブラウザの localStorage）は `skip` で送られ、ほかに話せる人がいる間は選ばれない（全員と話したあとは誰かが来て、今日もう話したことを伝える）。会話を持つ住人がいなければボタンは出ない。
  - 訪問者は人物の窓のいちばん上の「〇〇に話しかける」からも、その住人のいちばん新しい会話で話せる。会話はADV風（`GuildAdv`）：冒頭の定型の導入はなく、会話を書いた場所（`T_GUILD_TALK.place`）のカウンター越しの背景に住人の立ち絵が立ち、下のメッセージ枠に住人の最初のひとことが1文字ずつ出る（押す・Enter・スペースで全文→次へ）。続いて「あなた」の言葉として3つの返事が出て、選ぶとそれを「あなた」が話し、住人が返す。選んだ返事の返しだけを `GET /guild/talks/{id}/choices/{0〜2}`（公開・JSON）から取りに行く（返しはページに埋め込まない）。同じ住人とは1日1回（東京の日付）。話したこと・選んだ返事・返しと、前に選んだ返事は、ブラウザの localStorage にだけ残し、サーバーには訪問者の情報を何も保存しない（別のブラウザや削除後はまた話せる。厳密な1日1回ではない）。別の返事は別の日に選べ、前に選んだ返事には「（前に選んだ）」と出る。JSが動かない画面では最初のひとことだけを出す。
  - 話したあとは、人物の窓に今日のやりとり（住人のひとこと・あなたの返事・住人の返し）が吹き出しで残る。
  - 酒場と国の酒場では、話せる住人の頭の上に専用の吹き出し（「…」が点滅しながら小さく揺れる）が出る。故人とは話せない（会話も返しも出さない）。住人を削除すると、その人の会話も消える。
- 画面下のタブ（酒場・冒険・記録、管理者にはメンテ）から、各ページを酒場の上のウィンドウとして開く。来店者・住人名簿・依頼掲示板の窓は廃止した（住人とは酒場で出会う「一期一会」。`/guild/visitors`・`/guild/board`・`/guild/characters` は404）。
  - `/guild/characters/{id}`：人物詳細（この街での関係・最近の交流つき）。酒場の人物やリンクから開く。原記録は非公開。
  - `/guild/dungeon`：いちばん新しいダンジョン探索（公開済みの段階まで）とこれまでの探索。`/guild/dungeon/{id}`：1回の探索。
  - `/guild/log`：交流の記録（新しい順、30件ずつ）。本棚の形で、1日が1段、1場面が1冊（背表紙に要約を縦書き、色は種類ごと、高さは少しずつ違う。指すと少し引き出され、登場人物・時刻・場所が出る。押すと場面が開く）。住人・種類・今の関係で絞り込める。`/guild/log/{id}`：1件の場面と関係の変化。`/guild/pairs/{小さいID}-{大きいID}`：二人の物語。
  - どのURLも、酒場の上にそのウィンドウを開いた状態でサーバーが描く（JSなしでも、共有リンクでも同じ見た目）。JSがあれば、ギルド内のリンクはページ遷移せずにウィンドウを差し替え、URLも追従する（戻るで閉じる）。
- 管理者専用 `/guild/maintenance`：住人の追加・再試行（1日 `GUILD_DAILY_LIMIT` 人まで、既定5・上限5。大きい値を設定しても5人で止まる）、今日の来店者の引き直し、住人の削除、直近30件の実行結果。ポータルのメンテページから移動できる。
- 毎日21:00 **Asia/Tokyo** に、その日まだ誰も迎えていなければ1人追加する。
- サーバーの稼働時間（20:00〜23:30 **Asia/Tokyo**）に合わせ、毎日20:00〜23:15の15分ごと（各枠の3分過ぎ、1日14枠）に、同じ場所にいる今日の来店者のうち2人が交流する（1日最大12件。毎時0分の枠は必ず無人のギルド、ほかの枠は2人以上いる場所からランダム。下の「交流」）。誕生（21:00）・ダンジョン（21:50〜22:30）・住人との会話（22:30〜22:50）もこの時間に収まる。
- 毎日21:50 **Asia/Tokyo** に、無人のギルドの今日の来店者から1〜4人がダンジョンへ出発する（仮。下の「ダンジョン探索」）。出発直後にAIが4段階の物語を書く。
- 人物は名前・年齢・性別・職業・名前の系統・見た目・紹介・人となり・出身地・現在地・所属派閥・信仰・所属の履歴を持つ（下の「村・派閥・信仰」）。
- 人物は Bedrock の構造化出力を検証して保存。既存 `app.ai.model-id`、リージョン、AWS認証、`BedrockTextClient` を再利用する。画像APIは不要。

軽めの初回実装として、AIによる冒険の記述、数値気質、世界情勢・情報伝達・英雄、死亡を確定させるイベントは未実装。記録棚にはこの段階を明記しており、存在しない冒険記録は表示しない。生存・負傷・行方不明・死亡を保存でき、存命以外は通常来店から除外、人物詳細は残す。生死を変更する管理操作やランダムな死亡処理は用意していない。

## 有効化

Flyway V52 は既存テーブルを変更せず、ギルド専用のテーブルを作成する。V53（Java）は1日1人の一意制約を外し、V54 は年齢・性別・職業と記憶の見出しを追加する。V55 は名前の系統・見た目のパーツと、記憶の種類を追加する。

```dotenv
GUILD_ENABLED=true
GUILD_RECENT_DAYS=30
GUILD_RECENT_RATIO=0.5
GUILD_DAILY_LIMIT=5
GUILD_CATEGORY_WINDOW=10
GUILD_CATEGORY_CAP=3
GUILD_GENDER_CAP=7
GUILD_OCCUPATION_CAP=3
GUILD_LINEAGE_CAP=5
# 任意。公開する実際のURLが確定してから指定する。
# GUILD_PUBLIC_URL=https://<公開ホスト>/guild
```

既定では生成は無効。Bedrockを呼べる本番環境で `GUILD_ENABLED=true` を設定してアプリを再起動する。`app.ai.enabled` は既存の投稿スケジュールのスイッチであり、ギルドとは別。既存のAIモデル設定・AWS権限がそのまま必要。

有効時、起動30秒後から毎分、当日の来店名簿が未作成なら確定する。生成済み名簿は再抽選しない。新顔・久しく来ていない住人を優先し、ゲームの稼働状態は参照しない。人物がゼロなら空の日を確定せず、最初の誕生直後に来店できる。名簿確定後に追加した人物は新顔・名簿には即時表示され、来店は翌日以降。停止中の最終名簿を表示するときはその日付を明示する。

朝は00:00〜10:59、昼は11:00〜17:59、夜は18:00〜23:59（JST）。各時間帯の短い行動文をDBに保存し、閲覧では生成も書き込みも行わない。再読み込みで現在の時間帯を表示する。動きを減らすOS設定に対応。

## 記憶（出典）の選び方と公開範囲

住人は「記憶」から生まれる。記憶は、プレイの小さく具体的なひとまとまりと、その数行の記録。ログ全体は件数が多く偏るため、読むものを絞っている。

| ゲーム | 種類 | 記憶ひとつ | 記録の行 |
| --- | --- | --- | --- |
| 7 Days to Die | 訪れた場所 | 徒歩でPOIの80m以内に初めて入った（POIごとに1回） | 到着時刻＋その後3時間にそのPOIの近くで倒した敵（最大2件） |
| 7 Days to Die | 倒したもの | ある日に倒した、ある種類の敵 | その日の最初・中ほど・最後の3件（近くのPOIがあれば「古い家で〜を倒した」）。見出しにその日の数 |
| Terraria | 増えた蓄え | ある日の宝箱の増加 | 増えた量の多い順に、品物の分類が重ならないよう最大3件 |
| Terraria | 果たしたこと | 最新の取り込み時点で達成済みのボス・イベント（住人NPCは除く） | 「〜を討ち果たした」「〜を退けた」の1行。いつ果たしたかは扱わない（済んだことは済んだこととして） |
| Terraria | 宝箱の中身 | 管理下のチェストのうち半分以上埋まっているもの | 多い順に最大6種 |
| Core Keeper | 増えた蓄え | ある日の、ひとつの宝箱の増加 | 最大3件（装備は枠の数で数える） |
| Core Keeper | 果たしたこと | 最新の取り込み時点で達成済みのボス・大壁 | Terraria と同じ（大壁などは「〜を成し遂げた」） |
| Core Keeper | 宝箱の中身 | ラベル付きの箱のうち半分以上埋まっているもの | 多い順に最大6種 |

- 抽選: ゲーム → 種類 → グループ（敵の種類、POIの分類、日付など）→ 記憶 の順にどれも均等。よくいるゾンビや、記録の多い一日が他を押し流さない。直近30日とそれ以前を既定50:50（`GUILD_RECENT_DAYS` / `GUILD_RECENT_RATIO`、宝箱と果たしたことは最新の取り込み時点なので直近扱い）。
- 7DTD のログは今日より前の日だけ。宝箱は最新の取り込み時点の中身だけが保存されているため、見出しにその日付を書く。
- 名前表にない品物（`#7` など）は省く。全部省かれた記憶は使わず、引き直す。
- ネタバレ扱いの進捗は名前を出さず、ぼかした呼び名にする（例：「嵐を呼ぶ空の巨鳥」「砂の下を這う巨大な甲虫」。`GuildSourceService.EPITHETS`）。Core Keeper のボスの多くが該当する。呼び名のない進捗を後からネタバレ扱いにすると「正体の知れない大物」になる。AIには、呼び名から想像と知識で姿や伝承を膨らませ、正体は明かさないよう指示している。
- 偏りの上限: 直近 `GUILD_CATEGORY_WINDOW`（既定10）人のうち、同じ種類の記憶から生まれるのは `GUILD_CATEGORY_CAP`（既定3）人まで。上限に達した種類しか残っていない日は見送る（SKIPPED）。
- 使わなくなった記録: 7DTD の接続・死亡・ホード・補給物資・スリーパー・レベルアップ・乗り物・ブラッドムーン予定、Core Keeper の接続、Terraria の図鑑の討伐数。
- プレイヤー名・ID・座標・チャット・宝箱の名前やラベルは読まない。記憶の見出しと記録の行は人物ページの「生まれた記憶」に公開し、ソースキーは非公開。**宝箱の中身（品名と数）も記録の行として公開される**（宝箱の一覧ページはログインが必要だが、#91 以降、宝箱の増加は記憶として公開してきた）。住人を削除すると、その記憶はまた使われることがある。
- メンテページの「記憶の内訳」に、ゲーム・種類ごとの未使用の記憶の数と、直近の住人の種類を表示する。

### ブラッドムーン偏重の調査（2026-10-25、コードの確認のみ）

本番DBは見ていない。コードから分かった原因は次のとおり。

- #91 より前の版は、AIに「ある一日の接続記録。接続回数=N。行動や戦果は不明。」としか渡していなかった。中身のない入力と「7 Days to Die」という名前から、AIがゲームの代表的な出来事（ブラッドムーン）で人物像を埋めていたと考えられる。#89 時点で生まれた住人の偏りは主にこれ。
- #91 の版は実際の記録を渡すようになったが、7DTDで読む記録が討伐・接続・死亡・ブラッドムーンだけで、戦闘の色が強かった。さらに、ゲームの次は日を均等に選ぶだけで、記録の多い夜（ブラッドムーンの夜は討伐が集中する）の枠がそのまま選ばれやすかった。
- 対応: 種類の段を追加して種類ごとに均等に選ぶ、7DTDで探索・採集・遠出の記録も読む、ブラッドムーンの夜をひとつの種類にまとめる、直近の住人の種類に上限を設ける。実データでの分布は、デプロイ後にメンテページの「記憶の内訳」で確認する。

## 人物の決め方（V57）

記憶を選んだあと、AIが記録を読んで人物を決める。コードは材料と選択肢を用意し、結果を検証する。

1. **材料（その頃の世界）**: 記憶の記録に加えて、`GuildDossier` がその頃の世界の進み具合をまとめる。Terraria / Core Keeper は、記憶の時刻までに取り込まれた最新のスナップショットの達成率（ボス討伐・イベント・住人NPC・世界の変化）、達成済みの例（ネタバレ扱いはぼかした呼び名）、まだのボス（ネタバレ扱いは出さない）。7DTD は、ゲーム内の日数と、それまでに足を踏み入れた場所の数。
2. **選択肢**: 性別（女性・男性）、職業19種（農家、夜警、騎士、職人、鉱夫、商人、聖職者、冒険者、猟師、漁師、料理人、鍛冶屋、大工、薬師、運び屋、護衛、侍、浪人、巫女。侍・浪人・巫女は月影郷が選択肢にあるときだけ）、名前の系統5種。直近 `GUILD_CATEGORY_WINDOW`（既定10）人のうち、同じ性別が `GUILD_GENDER_CAP`（既定7）人、同じ職業が `GUILD_OCCUPATION_CAP`（既定3）人、同じ系統が `GUILD_LINEAGE_CAP`（既定5）人に達したものは選択肢から外す。直近5人の性別・職業・系統も渡し、似た人物を避けさせる。
3. **AIが決める**: reading（記録から読み取った手がかり、120字）、性別、職業、系統、名前、年齢、紹介、人となり。選択肢にない値、系統の規則に合わない名前は不正な応答として保存しない。記録の「誰か」を本人とみなさない・元プレイヤーの性別や性格を推定しない・記録にない戦果を作らない・数値や品名の一覧を書き写さない、をプロンプトで指示。
4. **書き方**: 記録の品物・場所・相手を、人物の持ち物・仕事道具・忘れられない場面・口ぐせ・願いとして具体的に再現するよう、想像力を高めに指示する（temperature 0.9）。ゲームの固有名詞は中世の街に合う言い方へ置き換えてよい。
5. **公開範囲**: reading は人物詳細の「生まれた記憶」に「記録から読み取られたこと」として公開。材料（その頃の世界）は `T_GUILD_SOURCE.world_facts` に保存し、メンテ画面の住人一覧でだけ見られる。

- 見た目はSDイラストのパーツ（`static/img/guild-people.svg`。96×144のベクター、生成元は `scripts/guild/generate-people.py`、詳しくは `scripts/guild/README.md`）の重ね合わせ: 体 → 目（9種類）→ 顔の補助 → 眉（3種類）→ 基本表情（性格文の言葉から、明るい・意志が強い・思慮深い・穏やか。該当なしは通常）→ 年齢（20歳未満・40歳以上・60歳以上）→ 脚（ズボンかスカート）→ 職業の服 → 髪型 → 小物 → 帽子。パーツ名・色はDBに保存済みの値をそのまま使い、再抽選しない。V70で目の形・眉の形・衣装差分を保存する列を追加し、既存住人にも目元の差分を一度だけ割り当てる。衣装は普段着・旅装・晴れ着の3差分（計72パターン）。メンテページの「目元を引き直す」は目と眉だけ、「外見を引き直す」は肌の色と人物設定を保って髪・服・小物などを再選択する。どちらもAIは呼ばず、結果を保存する。画像生成は使わない。
- 男女でパーツが分かれる（V60）：髪型はV70で計45種（男性21・女性24）に増やした。元の髪型は男性7種（短髪・刈り上げ・逆立ち・横流し・ぼさぼさ・髷・短い尻尾）と女性8種（ロング・ボブ・ポニーテール・三つ編み・ツインテール・お団子・ウェーブ・姫カット）。小物は男性（あごひげ・口ひげ・無精ひげ・眼帯・頬の傷・眼鏡）と女性（リボン・花飾り・耳飾り・ヘアバンド・眼鏡）。服は職業ごとの男性用と女性用（農家はエプロンドレス、商人・料理人はドレス、聖職者はベール付きなど）。侍・浪人・巫女には月影郷の装束（巫女の男性は白衣と袴に烏帽子）。髪色15・肌8・服16・差し色11・瞳7色をパレットから抽選。V60は既存の女性住人の服を女性用に、性別に合わない髪型を近いものに置き換える（色は変えない）。
- 名前の系統: 日本系は漢字かひらがな2〜6文字、ほかはカタカナ2〜8文字の名だけ。
- 既存の住人と同じ名前や、プレイヤー名（`M_PLAYER` / `M_CK_PLAYER`）を含む・含まれる名前は保存しない（FAILED）。AIはプレイヤー名を受け取らない。有名人・有名作品の人物名はプロンプトで禁止しているだけで、機械的には確認していない。
- Bedrockは1回最大1200出力トークン・45秒。

## 村・派閥・信仰（V58）

世界の土台。マスタ表（`M_GUILD_VILLAGE` / `M_GUILD_FACTION` / `M_GUILD_FAITH`）に置き、住人はそのキーを持つ。

| 区分 | 値 |
| --- | --- |
| 村 | グランフォード（西洋風。領主・騎士・農民）、エルムウッド（森林。狩人・薬草師、自然信仰）、月影郷（和風。侍・浪人・巫女） |
| 派閥 | グランフォード領主家・白銀の騎士団（グランフォード）、翠葉の守人（エルムウッド）、月影武家衆（月影郷）、無所属 |
| 信仰 | 暁光教（光と秩序）、精霊信仰（月影郷では「精霊信仰（八百万信仰）」と表示）、無信仰 |

- 住人の列：`home_village`（出身地）、`current_village`（現在地）、`faction`、`faith`。変化はすべて `T_GUILD_AFFILIATION_HISTORY`（種類 village/faction/faith、前後の値、initial/birth/move/join/leave/expel/convert、理由、原因の交流ID）に残る。故人の履歴も消えない。住人を削除したときだけ一緒に消える。
- 世界の規則（`GuildWorld`）：月影郷の生まれ ⇔ 日本系の名前。侍・浪人・巫女は月影郷だけ、騎士は月影郷にいない。派閥はその派閥の村に暮らす人だけが入れる。職業に侍・浪人・巫女を追加（服はそれぞれ夜警・冒険者・聖職者の服）。
- **既存の住人（V58の初期値）**：記録から言えることだけで決める。日本系の名前→月影郷、猟師・薬師→エルムウッド、それ以外→グランフォード。現在地は出身地と同じ。グランフォードの騎士→白銀の騎士団。聖職者→グランフォードなら暁光教、それ以外は精霊信仰。分からないものは無所属・無信仰。履歴に「記録から判断した初期値」として残す。
- **誕生**：AIは記憶と世界の説明（3村・派閥・信仰）を読んで、村・派閥・信仰も選択肢から選ぶ。村は直近 `GUILD_CATEGORY_WINDOW` 人のうち `GUILD_LINEAGE_CAP` 人、派閥は `GUILD_OCCUPATION_CAP` 人に達したものを外す（無所属は常に選べる）。月影郷と日本系は両方出すか両方外す。規則に合わない応答は保存しない。出産による誕生はない（記憶からだけ）。
- **交流での変化**：カードの結果が `change`（join：{b}の派閥に加入、leave：脱退、expel：追放、move：{b}の村へ移住、convert：{b}の信仰へ改宗）を持つと、コードが{a}の値を書き換え、履歴に交流IDつきで残す。そのカードは、変化が実際に起こせる組（無所属の人と派閥の人で村が同じ、など）にしか出ない。加入・改宗・追放・脱退は major（1日1件の枠を共有）、移住は progress。
- 派閥や信仰の違い・同じ・村の違い・最近の変化（14日以内）・元の派閥の人との再会（former）を条件にしたカードで、派閥間や信仰間の交流・対立、村をまたぐ出会いが起き、関係の数値も動く。組の選び方に affiliation（村・派閥・信仰の違う組、既定の重み2）を追加。
- AIへの入力は、その二人の村・派閥・信仰、二人に関わる村・派閥・信仰の説明だけ、直近の所属の変化（最大3件）、この場面で起きる変化。加入・脱退・追放・改宗・移住の語は、その場面でコードが起こしたか、どちらかが過去に経験したときだけ書ける（それ以外の応答は捨てる）。AIの呼び出し回数は増えない（誕生1回・交流1回のまま）。
- 表示：人物詳細に出身地・現在地・所属派閥・信仰・所属の履歴。交流の詳細に「所属の変化」。メンテ画面に存命の住人の村・派閥・信仰の内訳。
- 未実装（対象外）：経済、戦争、複雑な宗教、家族・出産、派閥ごとのAI、AIが村を作ること。

## 交流（V56、1日12件）

- `GUILD_INTERACTION_HOURS`（既定 `20,21,22,23`）の各時間に4枠（毎時3分・18分・33分・48分の実行。`slot_key` は `yyyy-MM-ddTHH:00` / `:15` / `:30` / `:45`）、各枠に最大1件。`GUILD_INTERACTION_END`（既定 `23:30`、サーバーが止まる時刻）までに終わる枠だけを使う（既定では23:15の枠が最後で、1日14枠。上限12件に対して、見送りがあっても12件に届きやすい余裕を持たせている）。`GUILD_INTERACTION_DAILY_MAX`（既定12）は12より大きくしても12で止まる。どの枠も夜（18時以降）なので、どのカードも夜に出られるようにしてある（時間帯の指定は「夜だけ」か指定なし）。それ以外の時間は何もしない（実行記録も残さない）。`T_GUILD_HOURLY_JOB.slot_key`（主キー、`yyyy-MM-ddTHH`、JST）と `T_GUILD_INTERACTION.slot_key`（一意）、共通ロックで、複数プロセスや手動実行と重なっても2件目は作られない。処理済み（成功・見送り・失敗）の時間は後から埋めない。
- 交流の場所（V66、`T_GUILD_INTERACTION.place`）：毎時の1枠目（`THH:00`）は必ず無人のギルドで、ほかの枠（`:15` / `:30` / `:45`）は存命の来店者が2人以上いる場所（ギルドと3国の酒場）から均等にランダム。参加者はその場所にいる人だけ。場所はAIへの入力（「場所=樫の盾亭（グランフォード）」など）に入り、国の酒場では国の風土に合った店のつくり・料理・音で書くよう指示している。記録の一覧と詳細に場所を添える。国の酒場の画面にも、その場所の最新の交流のせりふが流れる。V66より前の交流はすべてギルドでのものとして扱う。
- 参加者は今日の来店者のうち存命（ALIVE）の住人だけ。2人未満なら見送り（SKIPPED）。故人は参加せず、二人がともに親しみ20以上を持っていた故人は「追悼」の題材になる。
- 組の選び方は random / warm（好感度の高い組）/ cold（低い組）/ bond（知人より先の関係）/ thread（未解決の火種がある組）/ affiliation（村・派閥・信仰の違う組）を `app.guild.selection-weights`（既定 3:2:1:2:2:2）で抽選。合う組がなければ random。直近 `GUILD_RECENT_PAIR_SLOTS`（既定3）件に出た組は1/4の確率に下げる。
- 出来事は `src/main/resources/guild/event-cards.yml`（179枚。版 `version` を記録に残す）。会話の議題・結果・数値の変化はすべてこのカードで決まり、AIはそれに沿って場面を書くだけ。性別が同じ／違う（gender）、{a}が{b}を好みのタイプと感じている（smitten）、{a}の出身の村（a_home）、二人が同郷か（homes）も条件にできる。文中には職業（{a_job}）・出身の村（{a_home}）・派閥・信仰・暮らす村を差し込める。仕事の誇りや苦労、故郷の味や歌や言い伝え、3村それぞれの文化（グランフォードの収穫祭・馬上槍試合、エルムウッドの精霊祭・薬草、月影郷の月見・茶の作法・神楽など）、信仰や派閥の話題を含む。daily / progress / thread / major の段階があり、告白・求婚・弟子入り・決裂などの major は酒場全体で1日1件まで。条件（関係・時間帯・数値・火種・成人・年齢差・クールダウン）に合うカードから重みで引き、結果と数値の増減もコードが抽選する。
- 関係は向きのある4軸（信頼・親しみ −100〜100、警戒・恩義 0〜100）と、二人で1つの関係名。関係名を動かすのはコードの規則だけ：
  - 知人→友達（親しみ30以上・2回以上）、知人→仲間（信頼40以上・協力的な交流2回以上。自動冒険がまだないため、相談・協力・手合わせ・指南を協力的な交流として数える）、→親友（親しみ60以上・信頼50以上・5回以上）、親しみが0未満なら知人へ戻る。
  - 恋人：告白カードの成功＋双方成人＋親しみ50以上＋どちらにも恋人・配偶者がいない。配偶者：恋人になって7日以上＋親しみ70以上＋信頼60以上で求婚カードが成功したとき。恋人と配偶者は同時に1人まで。
  - 宿敵：決裂カード＋警戒60以上か親しみ−40以下。知人へ戻るのは和解カードで警戒30未満になったとき。師弟：弟子入りカード＋10歳以上の年齢差＋弟子から師への信頼30以上。
- **関係が動く速さ（1日12件に合わせた調整）**：交流は町全体で1日12件なので、同じ二人が会うのはたまにしかない。以前のカードどおりの増減（1〜3）では、30日間のシミュレーション（住人30・60・120人、AIなし・定型文）で友達が1組も生まれなかった。いまは次の4つで動かしている（いずれもコードの定数）。
  - カードの増減を3倍にする（`PACE`。下がる方も3倍なので、口論や決裂も重くなる）。さらに、その側にとって悪くなかった交流（親しみ・信頼が下がらず、警戒が上がらない）では、カードに関係なく親しみ+3・信頼+2（`FAMILIAR_*`。会うほど慣れていく）。
  - 二人とも親しみ10以上で前に会ったことがある組は、話す組に3倍選ばれやすい（`REUNION`。直近の枠に出た組を下げる規則はそのまま）。
  - 親しみ30以上（二人とも）か、知人より先の関係の組では、進展・火種・大きな出来事のカードが4倍出やすい（`DEPTH`）。大きな出来事は、カードの条件より10以上進んでいる（たとえば親しみ40で出せる告白を、二人とも50以上で迎えている）と、さらに5倍出やすい（`RIPE`）。警戒20以上か親しみ−10以下の組では、口論と進展・大きな出来事のカードが4倍出やすい。
  - 来店の名簿を作るとき、来店者は半分の確率で、その場所に来られる人のうち自分の親しみが5以上で高い方から3人のうち1人を連れてくる（`GuildService.COMPANION_*`）。連れは、順番待ちの最後の人の席に入る。同じ日にほかの場所にいる人は連れてこない。
  - 同じシミュレーションを60日回した結果（1回ずつで、ぶれは大きい）：住人40人では、2週目に恋人、30日で友達8組・親友1組、60日で友達14組・親友4組・恋人3組・夫婦1組。住人80人では、60日で友達10組・親友2組・恋人3組。住人150人では、60日で友達9組（恋人はまだいない）。本番の住人数と実際の動きは未確認。
- **うわさ・嫉妬・疎遠（V71、`GuildRumors`）**：すべてコードで決め、AIは呼ばない。
  - うわさ：交流で関係名が恋人・夫婦・宿敵・親友・師弟に変わったとき、または派閥・信仰・暮らす村が変わったとき、コードが決まった文（「リネとロアンが恋仲になったらしい。」「リネが銀の騎士団に加わると聞いた。」など）を作る。二人のどちらかに親しみ10以上を持つ存命の住人から最大3人（ランダム）が聞き、その人の「今思っていること」になる（`T_GUILD_THOUGHT.kind = 'rumor'`）。うわさも次の交流や住人との会話でAIに渡る。その日のうちに聞いた人は、酒場のひとりごとの吹き出しでそのうわさをつぶやく。人物の窓では「噂」の印をつける。
  - 嫉妬：恋人か配偶者がいる人に、ほかの人が近づいたとき（その人を好みのタイプと感じていて親しみ40以上になり、さらに上がったとき、または異性どうしで新しく親友になったとき）、半分の確率で相手の恋人・配偶者がそれを聞く。聞いた人は、近づいた人への親しみ−6・警戒+9、自分の恋人への信頼−3になり、「〇〇が〇〇と親しくしているらしい。胸がざわつく。」が今思っていることになる。変化はその交流の記録に「噂：…」として残る。
  - 疎遠：会わない（交流・ダンジョンで関係が動かない）まま10日たった関係は、親しみが3下がる（10未満にはならない）。その後も10日ごとに同じだけ下がる。夫婦は下がらない。うわさや嫉妬で動いた分は会ったことに数えない。交流の各枠の最初に、まとめて処理する。
  - 60日のシミュレーション（住人40人、1回だけ）では、うわさ25件・嫉妬3件。友達19組・親友4組・恋人4組で、疎遠を入れる前とほぼ同じ。住人80人では、うわさは3件と少ない（このときの親しみの条件は20。いまの10より厳しかった）。
- 火種（約束・借り・遺恨・探し物・片思い）はカードの結果で生まれ、期限（日数）を過ぎると立ち消え（FADED）、対応するカードで片づく（RESOLVED）。
- AIが書くのは情景（140字）とせりふ（4〜8行、各60字）だけ。入力は時間帯・種類・決まった結果・二人の年齢/性別/職業/性格・話し方・関係・変化・火種で、プレイヤーの情報は含まない。話題を一つに絞って具体的に掘り下げ、相づちだけのせりふを避け、二人の違いが掛け合いになるよう指示している。
- **いま思っていること（V69、`GuildThoughts`・`T_GUILD_THOUGHT`）**：AIは場面と一緒に、二人それぞれの「今思っていること」と「相手について思っていること」（各40字未満、本人の心の声）を `thoughts` として返す。行は追記するだけで、最新の行がその人の現在地になる。次にその二人が交流するとき、AIには各人の今思っていること・相手について思っていること・前に二人で話したこと（直近2件の日付と要約）が渡され、毎回ではなく自然に前の続きを書けるようにしている。住人との会話（V67）にも、その人の今思っていることを話題のヒントとして渡す（ほかの住人の名前は出さない決まりのまま）。思っていることは場面より甘く扱い、二人以外の名前・同じ人の重複・長すぎる文・入力にない結婚や死などの変化を含むときは思っていることだけを捨て、場面は残す。定型文に切り替わった交流では保存しない。人物の窓に「今、思っていること」（吹き出し）と、その前の4件（日付つき）、関係一覧の各相手への思いを表示する。交流を消すと（住人の削除）その交流から生まれた思いも消える。
- 話し方（`GuildVoice`、保存しない）：子ども（15歳未満）・年配（60歳以上）・月影武家衆・性格の言葉（内気／ぶっきらぼう・気が強い／丁寧／明るい／穏やか）・丁寧に話す職業（商人・神官など）の順に決まり、どれでもなければ性別ごとの日常の話し方3種からidで固定。男女で一人称と語尾が分かれる（例：明るい女性は「わたし／〜だよ・〜なの」、ぶっきらぼうな男性は「俺／〜だ・〜だな」、さばさばした女性は「あたし／〜だろ・〜さ」、年配の男性は「わし／〜じゃ・〜のう」）。性格に「一人称は「〇〇」」とあればそれを使う。人物の窓に「話し方」として表示する。話者が二人以外、または入力にない結婚・交際・宿敵・弟子入り・死を書いた応答は捨てる。
- AIが失敗したとき、`GUILD_INTERACTION_FALLBACK=template`（既定）ならカードの定型文で同じ結果を保存し、`skip` ならその時間を FAILED として見送る。Bedrockは1回最大2000出力トークン・60秒。
- **定型文ばかりになる問題の対策**：以前は出力上限が1100トークンで、日本語の8行の掛け合いでは途中で切れてJSONとして読めなくなることがあった。せりふ（60字の指示に対して70字）や情景（140字の指示に対して180字）を少しでも超えると場面ごと捨てていた。さらに「殺風景」「相殺」のような語も「殺」として、話者名に「（28歳）」が付くだけでも不採用にしていた。いまは、上限2000トークン、せりふ100字・情景220字・せりふ10行まで受け入れ、話者名の付け足しは許し、「殺」は殺す行為の言い方だけを見る。条件に合わない応答は1回だけ頼み直す（1件あたり最大2回の呼び出し）。それでも定型文になった枠は、実行記録に「定型文（AIの応答を不採用：せりふが長すぎる）」「定型文（Bedrockを呼び出せず：…）」のように理由を残す（理由は短い決まった文で、AIの応答そのものは残さない）。
- **性別と好み（V59）**：好感度の伸びは向きごとに別々に抽選し（「両方」の増減も片側ずつ）、さらに性別で変わる。同性（または性別不明）はカードどおり。異性は、親しみ20未満のうちは増える分が3分の2になり、4回に1回は増えない。ただし成人どうしの異性が初めて会ったとき、20%の確率で片方が相手を「好みのタイプ」と感じ（`T_GUILD_RELATION.smitten`、向きのある値で一度決めたら変わらない）、その向きの親しみは大きく増える（増加量×1.5＋1）。好みのタイプを感じている側の親しみが40以上で、相手からの親しみが20未満なら、片思い（火種 crush、21日）が自動で生まれる。V59は既存の関係のうち成人の異性どうしにも同じ20%で設定する。
- AIには二人が同性か異性か、好みのタイプで気になっているか（相手は知らない）を渡し、気持ちは態度でにじませ、口に出させない。人物詳細の関係一覧に「気になっている」と表示する。
- 交流の記録（一覧・二人の物語・詳細）には、各人の年齢・性別・職業・暮らす村・派閥（無所属は省略）を名前に添えて表示する。
- 交流の詳細は、場面の最初のモノローグ（だれかが話す前の地の文。なければ「〇〇。カウンターの向こうで、話し声がしている。」）だけを、その場所の背景の上に霧から浮かぶように見せ、「会話を聞く」で始める。ADV（`GuildAdv`）は、その場所（ギルド・3国の酒場で背景が違う：ギルドは板壁と酒瓶の棚、グランフォードは石壁と旗、エルムウッドは木の壁と苔の灯り、月影郷は障子と提灯）のカウンター席から聞いている形：二人の立ち絵はカウンターの向こうに立ち（話している方を明るく、もう一方を暗く）、手前のカウンターに自分の杯がある。地の文は枠に入れず、画面が霧に包まれて文字がにじみ出る（押すと全文→次へ）。冒頭の定型文はなく、最後に「……話し声は、やがて酒場のざわめきに溶けていった。」が入る。メッセージ枠と文字は大きめ（文字は18〜23px）。吹き出しで並べた全文は「会話をすべて読む」に畳んで残す（一人目の住人は左、二人目は右。日本語は文節の切れ目で折り返す `word-break: auto-phrase`）。
- 酒場の画面は、今の時間帯（朝0〜11時・昼11〜18時・夜18時〜）に起きた最新の交流があれば、その二人の吹き出しをせりふに替え、下に「いまの酒場」として要約を出す。
- メンテ画面に直近24枠分の実行結果と「この時間の交流を起こす」ボタン（交流の枠の時間で、まだ空いているときだけ交流が起きる）。住人の削除では、その住人が出た交流・関係・火種も消える。
- 未実装：数値気質による補正、週のまとめ、自動冒険との連動。カードの重みや閾値は実データを見て調整する前提。

## ダンジョン探索（V61・V62、仮）

- 毎分（30秒）の確認で、`GUILD_DUNGEON_DEPARTURE`（既定 `21:50`、JST）から探索が終わる時刻までの間に、その日まだ出発していなければ出発する。1日1回（`T_GUILD_EXPEDITION.expedition_date` 一意＋共通ロック）。停止中で時間帯を過ぎた日は出発しない。メンテ画面の「今日の探索をいますぐ出発させる」は時刻を問わず出発させる（これも1日1回）。
- 参加者は無人のギルドの今日の来店者（国の酒場にいる人は除く）のうち存命の住人から、1〜4人を均等な人数でランダムに選ぶ。来店者がいなければ出発しない。
- 出発の時点で、プログラムが最後までシミュレートして保存する：ダンジョン（6か所）、目的（探し物・魔物を追い払う・奥の調査）、起・承・転・結それぞれのカードと主役、結果（踏破・一部達成・撤退）。カードは `src/main/resources/guild/dungeon-cards.yml`（42枚、版を `cards_version` に記録）。
  - 職業を役割（戦い・斥候・癒し・ものづくり）に分け、役割のある人がいるときだけ出るカード、目的ごとのカード、ダンジョンの近くの村の生まれの人が主役になるカード、2人以上のときだけのカードがある。
  - 「転」は危険度1〜3。その危険に対応できる役割の人がいれば、その人が主役になって別の文章になり、危険度が1下がる。人数・戦える人・癒せる人・運（0〜2）と危険度で結果が決まり、「結」は結果に合うカードから引く。
- 「〇〇中」は公開済みの最後の段階で決まる：出発直後は「〇〇へ向かっている途中」、起のあとは「探索中」、承のあとはカードごと（「鉄格子をこじ開け中」など、指定がなければ「奥へ進行中」）、転のあとは危機ごと（「戦闘中」「ボスと対決中」「落盤から避難中」など、転のカードは必須）、結のあとは「〇〇から帰還（踏破）」。段階ごとの値は保存時に `T_GUILD_EXPEDITION_STAGE.doing`（V62）へ書き、公開前は読み出さない。
- 段階は `GUILD_DUNGEON_STAGE_MINUTES`（既定10）分ごとに公開する：出発21:50、起22:00、承22:10、転22:20、結22:30。公開前の文章と結果は、公開の画面にもHTMLにも出さない（SQLの段階で隠す）。
- 戻ったあと（結の公開時刻を過ぎて最初の毎分の処理で1回だけ。`T_GUILD_EXPEDITION.settled_at`、V63）、仲間どうしの関係が双方向に変わる：踏破は信頼+5〜9・好感+3〜6、一部達成は信頼+2〜5・好感+1〜3、撤退はたいてい信頼-2〜-5・警戒+2〜5（35%で、生き延びたことで信頼+2〜4）。異性どうしの好感は酒場と同じく控えめに上がる（好みのタイプなら大きく）。変化は `T_GUILD_RELATION_EVENT` に探索のid（`expedition_id`）付きで残し、探索の窓に「仲間との関係」として出す（交流の記録の一覧には出さない）。1人での探索は変化なし。V63より前に戻った探索は変化なしで処理済みにした。
- 出発した人はその日の交流（22時・23時の枠）に加わらない。酒場の画面からは探索中いなくなり、戻ったあとは席に戻って結果に合った一言（戦利品を並べている、など）を言う。部屋の上のバーの「ダンジョン」ボタン（探索中は「探索中」の札つき）を押すと、酒場の絵がその夜のダンジョンの場面に切り替わる（店内の場所と同じ切り替えで、JSなしでも動く。「店内」の場所を選ぶと元に戻る）。場面は6か所それぞれの背景（坑木、色硝子、光る苔、霧、鳥居、水路）と松明をCSSで描き、出かけている住人がドット絵で歩く。上に「古い坑道で戦闘中」のような今の状況と起承転結の進み具合、下に公開済みの最新の段階の文章と次の知らせの時刻を出す。転の危機の間は、行く手に黒い影（目が赤く光る）が立ちふさがる。戻ったあとは住人はいなくなり、「〇〇から帰還（踏破）」と結の文章が残る。
- 人物詳細に、その人が行った探索（最新5件）。住人を削除すると、その人が参加した探索ごと消える。
- **AIによる物語**：出発のあと（同じ毎分の処理で、出発の取引とロックの外で1回だけ）、`GuildDungeonWriter` がカードの文章を「筋」として4段階を書き直し、`T_GUILD_EXPEDITION_STAGE.body` を差し替えて `written_by = 'ai'` にする。展開・主役・結果はコードの決めたまま。
  - AIへの入力：ダンジョン（名前・様子・棲むもの・眠る品）、目的、結果、仲間の名前・年齢・性別・職業・性格、各段階の主役・筋（カードの文章）・その後の「〇〇中」。プレイヤーの情報は含まない。
  - 応答は `{"stages":[起,承,転,結]}`。各20〜200字、仲間の名前を含むこと、仲間以外の住人の名前・死亡・結婚・交際・派閥や信仰の変化・移住の語を含まないこと、結が結果に反しないこと（踏破なのに撤退、撤退なのに踏破）を検証し、外れたら捨てる。
  - 最初の段階の公開まで2分以上あるときだけ書き、差し替えは1つのUPDATEで4段階まとめて（その間に段階が公開されていたら何もしない）。失敗したら定型文のまま。再試行はしない（同じ探索をAIに頼むのはアプリの起動中1回まで）。Bedrockは1回最大1600出力トークン・45秒。
  - メンテ画面の手動出発でも、続けて物語を書く。
- 未対応：探索による数値・所持品・負傷の変化。

```properties
GUILD_DUNGEON_DEPARTURE=21:50
GUILD_DUNGEON_STAGE_MINUTES=10
```

## 再試行・障害

- 管理者でログインし、メンテページの「今日の住人を追加 / 再試行」を押す。POSTには既存のCSRF保護が必要。
- 1日の上限に達したら追加しない。失敗・素材不足はメンテ画面で確認でき、当日の試行は上限＋5回まで。失敗は「Bedrockの呼び出し」か「応答の形式」かを例外のクラス名付きで表示する。生のAIレスポンスやエラー内容は保存しない。
- 生成は最大1200出力トークン、1回45秒のAPI時間上限。外部呼び出しのアプリ側自動リトライはしない（共通SDKの通信リトライは45秒内）。
- DBの共通ロックと日付・出典の一意制約で、複数プロセス・手動と定時の競合を防ぐ。人物、出典、必要なら初回名簿を一つのトランザクションで確定する。
- 正常な生成エラーは `T_GUILD_JOB` にFAILEDとして保存。DB障害やプロセス終了ではトランザクション全体が戻るため、途中の人物は残らず、当日の手動再実行が可能。この場合、ロールバックされた試行回数は残らない。
- 21時にアプリが停止していた日は自動追生成しない。復旧当日に管理者が実行可能。過去日のバックフィル操作は未実装。
- 有効化を止めても既存の人物と最後の来店名簿は閲覧できる。

## プレビューと検証

```sh
./mvnw -Dtest=GuildTests,CognitoSecurityMvpTests test
./mvnw clean package
node --test src/test/js/*.test.cjs
```

`GuildTests` はH2の隔離DBで、酒場の配置（会話の組は同じ卓、全員が一度ずつ、同じ日と時間帯なら同じ配置）、ダンジョン探索（出発の時間帯・1日1回・段階の公開・交流からの除外・削除）、同日並列生成、出典重複、非公開情報、権限・CSRF、不正AI出力、再試行上限、人物不足、日付・時間帯、存命以外の除外、名簿固定を確認する。AWSを呼ばず、Bedrock応答はテスト用固定値。`target/guild-preview` に、明示的な架空人物による表示確認用HTMLも出力する。

PostgreSQLでも同じテストを実行できる。**削除可能な専用DBだけ**を指定すること（テストはギルドのテーブルをクリアする）。

```sh
GUILD_TEST_POSTGRES_URL=jdbc:postgresql://127.0.0.1:<port>/postgres \
GUILD_TEST_POSTGRES_PASSWORD=<test-password> \
./mvnw -Dtest=GuildPostgresTests test
```

ローカル実DBは読み取り調査のみ。2026-10-25の確認では、マスタ未連携の7DTD接続記録2件、CKセッション0件、検証済み世界スナップショット0件だった。本番・実ログを使ったBedrock生成はこの実装作業では実施していない。

## 専用ドメイン

まず既存ポータルの `/guild` で利用できる。希望ドメインは未指定のため購入・DNS・公開操作は行わない。

`infra/nginx/guild.conf.example` は同じアプリへの公開用ホスト設定例。`/guild`、`/css/`、`/img/`、`/js/` のみ通し、`/` は `/guild` へ転送する。管理操作とログインは既存ポータル側で行うため、新しいCognitoクライアントや認証コールバックの追加は不要。

接続時には、希望ホスト名・DNSを変更できるアカウント・そのホスト用証明書を用意し、Nginxのホスト名/証明書パスを置換する。`GUILD_PUBLIC_URL=https://<ホスト>/guild` を設定すると酒場のcanonical/OG URLが固定される。実DNS接続と公開は別途行う。
