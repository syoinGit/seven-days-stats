# コミット前の改修記録（2026-10-17）

今回の差分は、作業開始時点の未コミット変更に対する追加改修です。
Javaの機能別構成、認証、投稿・リアクション、データ取り込み、AI生成、DBマイグレーション、
画面とJavaScript、起動・デプロイ設定を確認しました。

## 不具合と修正

| 対象 | 修正前の問題 | 修正内容 |
| --- | --- | --- |
| 投稿の所有権 | 現在のプレイヤー連携から削除権限を判定し、連携変更で過去の投稿の権限が移る | 投稿者アカウントIDを保存し、表示・削除の両方で使用 |
| リアクション | 同時操作で初回リアクションの一意制約違反や削除との競合が起こり得る | 投稿行をロックし、操作をトランザクション内で直列化 |
| 投稿サービス | 画面側の権限制御だけに依存し、サービス単独ではVIEWERの操作を拒否していない | 作成・リアクション・削除のサービスでもPLAYER/ADMINを確認 |
| タイムライン | offsetが600を超えると同じページを返す | ページ位置を正しく進め、過去の投稿を取得可能に |
| リアクション表示 | 12投稿で最大24回の関連問い合わせ | 1ページにつき1回の一括取得。件数取得だけの箇所はCOUNTに変更 |
| 無限スクロール | 次ページの有無だけが必要なのに全件数を集計 | Sliceを使用し、全件数集計を省略 |
| データ取り込み履歴 | 失敗時にFAILEDの履歴もロールバックされる | 実行履歴を独立したトランザクションで保存 |
| ログ取り込み | ファイル直接取込・Dockerストリームで、関連する複数の保存が原子的でない | ファイル・Telnet応答・Dockerイベント群ごとにトランザクション化 |
| 取り込み例外 | DB例外まで不正なログ行として処理する | DB例外を伝播し、その単位の保存を取り消す |
| ストリーム再試行 | DB保存とメモリ上のプレイヤー状態・読み取り済みバッファが一致しない可能性 | コミット後に状態・バッファを更新。失敗したイベントを再試行可能に |
| AI日記 | JSON抽出がクライアントごとに異なり、空・nullタグも受理する | JSON抽出を共通化し、タグを検証 |

## 構成の整理

- `DashboardController`は画面表示、`DiaryController`は日記、`PlayerInteractionController`は投稿・ステータス操作を担当。
- `TimelinePage`が保存済みタイムラインの表示変換を担当。実運用から呼ばれていない旧タイムライン合成処理を削除。
- `TimelinePostService`へ投稿操作を集約し、単なる委譲と旧表示モデルだけを持つ`PlayerSocialService`を削除。
- `ServerOverviewService`へサーバー計測値の取得・健康状態・グラフ生成を分離。
- `BedrockTextClient`と`JsonObjectResponse`を共有し、各AIクライアントはプロンプトと意味上の検証を担当。
- ローカル認証とCognitoのブラウザ向けセキュリティヘッダーを共通化。認証方式ごとの許可オリジンは維持。
- `POSTGRES_PORT`でアプリとComposeのポートを揃えられるようにし、ComposeにDBのヘルスチェックを追加。

## DB変更

V1〜V39の既存マイグレーションは編集せず、以下を追加しています。

- **V40**: `T_TIMELINE_POST.author_account_id`と外部キーを追加。
  旧投稿テーブルに残る投稿者ID、または既存の`source_hash`に記録されたアカウントIDだけから移行します。
  現在のプレイヤー連携からの推測は行いません。不明な投稿者はnullのまま保存し、削除権限を他人へ割り当てません。
  アカウント削除時は投稿を残し、投稿者参照だけをnullにします。
- **V41**: ゲーム・公開状態・投稿日時、ゲーム・投稿種別・投稿日時、プレイヤー・スナップショット日時の複合インデックスを追加。

認証アカウントと取り込みプレイヤー、現在状態と履歴、AI日記と公開タイムラインは役割が異なるため維持しています。
既存の旧投稿テーブルは履歴保全と投稿者移行に利用し、再バックフィルや削除は行っていません。
新インデックスの本番データ量での効果・作成時間は、実際のデータ分布に依存します。
